# Pokyny externému auditorovi EA-041

1. Auditujte iba otázky a T1 hranicu z dokumentu 00.
2. Z koreňa projektu spustite R6 package preflight cez PowerShell 7+ a
   zapíšte presný príkaz, exit code a wall time.
3. Overte manifest `15/15`, source/copy paritu, package `22`, response `1`,
   `REPRO=0`, runtime rows `0`, nulové duplicity a dočasné súbory.
4. Nevykonávajte Python; balík nemá runtime ani generated JSON.
5. Nezávisle prepočítajte B3 identity `nu_J epsilon_J=j_D` pre F1–F3 a
   skontrolujte deterministic/distributed event-energy rozlíšenie.
6. Overte B4 priamo proti A2, A7 a A12. Oddeľte neprítomnosť produktového
   protipólu od tvrdenia, že produktové udalosti fyzicky neexistujú.
7. Overte presných osem položiek Q4-P0 a zvlášť dodatočné Q22a-G0/AR46
   požiadavky na štvorvektor, tlak, shear, entropiu, šum a korelácie.
8. Skontrolujte, či historické `epsilon_eff^2` patrí spoločnému
   `F intersection I` v konkrétnej K1 hypotéze a či sa neoprávnene neprenáša
   z neskorého A1 do skorého rezervoára.
9. Posúďte úplnosť minimálneho nového vstupu, nie jeho estetiku. Jednoduchý
   ledger je prípustný, ale nesmie chýbať konzervácia ani momenty.
10. Každú odchýlku klasifikujte ako integrity, formal, dimensional,
    conservation, physical, documentation alebo scope/tier.
11. Vlastný nový model auditora je iba `DECLARED_DEVIATION`; nesmie meniť
    tier, projektový verdict ani skóre.
12. Aplikujte `EVIDENCE/010` ako exact AR66.2 checklist.

Povinné ledger termíny: `generated JSON`, `exit code`, `wall time`,
`odchýlka`.
