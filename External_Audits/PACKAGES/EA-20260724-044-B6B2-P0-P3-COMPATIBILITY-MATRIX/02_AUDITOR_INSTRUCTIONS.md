# Pokyny externému auditorovi EA-044

1. Pracujte iba s týmto sealed balíkom a auditujte iba otázku a T1 hranicu
   z dokumentu 00.
2. Najprv načítajte `EVIDENCE/011` až `015`, overte ich exact hashe a
   separation-of-duties identity voči charteru.
3. Spustite deklarovaný R6 package preflight cez PowerShell 7+ a zapíšte
   presný príkaz, exit code a wall time.
4. Overte manifest `15/15`, source/copy paritu, package `22`, response `1`,
   `REPRO=0`, runtime rows `0`, nulové duplicity a absenciu temp súborov.
5. Nevykonávajte Python, solver, P4 witness ani download dát. Balík nemá
   runtime, official vetvu ani generated JSON.
6. Auditujte úplnosť P0–P3 osi voči dokumentu 249 bez požiadavky na
   ontologicky vyčerpávajúci mikroskopický katalóg.
7. Overte, že compatibility je fibered product nad spoločnou base, nie
   slepý Cartesian product, a že quotient používa úplný `R_test`.
8. Overte typovanie retarded response/commutator supportu, classical
   covariance/common-cause/initial-state correlation domainov a
   real/complex/two-time/spectral/quantum positivity/null contracts.
9. Overte `AP-BASELINE-ALL`, presné atomic profile IDs, domain/class
   binding a ich inheritance vo F01–F09.
10. Pre každý exclusion certificate skontrolujte exact scope, dôkazovú
    triedu a záver `PRECHECK_EXCLUDED_SCOPE`; `NOT_EXCLUDED` nesmie znamenať
    existenciu a E2/E3 nesmú samy vydať STOP.
11. Overte conservation/no-double-count, bilateral quantum nulls, recovery
    limity a zachovanie unresolved residual bucketu.
12. Posúďte, či jediný bounded P4 witness attempt s local dependency freeze
    je najmenší successor; zlyhanie jedného ansatzu nesmie zabiť celý fiber
    alebo MF rodinu.
13. Každý hlavný záver označte dôkazovým tagom a osobitne uveďte dopad na
    package tier a fyzikálny verdict.
14. Každú odchýlku zapíšte explicitne; z T1 balíka nevydávajte computed,
    observačný, family-choice ani projektový verdict.

Povinné ledger termíny: `generated JSON`, `exit code`, `wall time`,
`odchýlka`.
